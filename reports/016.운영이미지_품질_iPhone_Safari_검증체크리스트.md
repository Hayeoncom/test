## 2. 작업 배경

015 작업에서 GitHub Pages artifact 경량화가 적용되었다. 원본 이미지와 URL 구조는 유지하고, `.pages-dist`에 복사되는 JPG/PNG만 최적화하는 방식이다.

015 검증에서 운영 HTML 19개와 이미지 942개 응답은 확인됐지만, 실제 iPhone Safari 수동 확인과 전체 이미지 개별 육안 품질 검수는 사용자 확인 항목으로 남았다. 이 문서는 실제 기기 검증을 같은 기준으로 기록하기 위한 체크리스트다.

## 3. 검증 목적

- 실제 iPhone Safari에서 운영 이미지 품질을 확인한다.
- 홈 하단 overlay, footer, Tokyo/Fukuoka 번호 순서, 가로 overflow를 확인한다.
- Chrome viewport 자동 검증과 실제 iPhone Safari 수동 검증의 역할을 분리한다.
- 실패 항목을 후속 수정 작업으로 넘길 수 있도록 URL, 기기, 재현 절차, 스크린샷 여부를 기록한다.

## 7. 이미지 품질 기준

### 기본 확인 항목

각 대표 이미지에서 다음을 확인한다.

1. 이미지가 로드되는가
2. 이미지가 깨져 보이지 않는가
3. 과도하게 흐려 보이지 않는가
4. JPEG 압축 노이즈가 과도하지 않은가
5. 피부, 하늘, 벽면 등 넓은 면에서 block artifact가 눈에 띄지 않는가
6. 어두운 영역의 계조가 과도하게 무너지지 않는가
7. 선명해야 할 피사체 윤곽이 지나치게 뭉개지지 않는가
8. 세로/가로 비율이 왜곡되지 않는가
9. 이미지 crop이 의도와 다르게 보이지 않는가
10. 고해상도 화면에서 품질 저하가 눈에 띄지 않는가

### 판정 기준

| 판정 | 의미 |
| --- | --- |
| PASS | 운영 사용 가능 |
| FAIL | 운영 품질 문제 있음 |
| HOLD | 사용자 육안 판단 필요 |
| N/A | 해당 페이지 또는 항목에 적용 불가 |

### FAIL 기준

다음 중 하나라도 해당하면 FAIL로 기록한다.

- 이미지 404 또는 로딩 실패
- 이미지가 빈 영역으로 표시됨
- 이미지 비율 왜곡
- 모바일 화면에서 핵심 피사체가 과도하게 잘림
- 텍스트 overlay와 이미지가 겹쳐 읽기 어려움
- 압축 노이즈가 사진 감상을 방해함
- 원본 의도와 다르게 지나치게 흐림
- 가로 스크롤 발생

## 8. 레이아웃 검증 기준

### 홈 하단 overlay

- overlay 텍스트가 이미지 영역 안에 있는가
- overlay 텍스트끼리 겹치지 않는가
- overlay 텍스트가 잘리지 않는가
- overlay 텍스트 대비가 충분한가
- 이미지 로딩 전후 layout shift가 과도하지 않은가
- 작은 iPhone 폭에서 텍스트가 이미지 밖으로 밀리지 않는가
- overlay가 `position: absolute` 기반으로 유지되는가

### footer

- footer가 의도한 위치에 표시되는가
- `©` 기호가 실제 기호로 표시되는가
- literal `&copy;` 문자열이 노출되지 않는가
- `Hayeon 2018-2026` 텍스트가 깨지지 않는가
- 모바일 폭에서 footer 텍스트가 잘리지 않는가

### Tokyo/Fukuoka 번호 순서

- 번호가 시각적으로 1 -> 2 -> 3 순서로 표시되는가
- `#number`, `#number2` 컨테이너가 서로 섞이지 않는가
- 모바일 폭에서 번호가 줄바꿈되더라도 읽는 순서가 유지되는가
- 숫자가 겹치거나 잘리지 않는가
- viewport별로 순서가 달라지지 않는가

### 가로 overflow

- 페이지 전체에서 가로 스크롤이 발생하지 않는가
- 이미지가 viewport 밖으로 밀리지 않는가
- overlay 또는 번호 영역이 viewport 밖으로 나가지 않는가
- 특정 카드 또는 이미지 섹션만 가로 overflow를 만들지 않는가

## 10. iPhone Safari 수동 검증 절차

1. iPhone Safari에서 `https://hayeon.kr`에 접속한다.
2. 캐시 영향을 줄이기 위해 주소창 새로고침을 1회 수행한다.
3. 문제가 의심되면 Safari 탭을 닫고 새 탭에서 다시 접속한다.
4. 홈 첫 화면에서 slider 이미지가 로드되는지 확인한다.
5. 홈의 travel card 영역을 확인한다.
6. 홈 하단 document overlay 영역으로 이동한다.
7. overlay 텍스트가 이미지 위에 유지되고, 텍스트끼리 겹치지 않는지 확인한다.
8. footer까지 스크롤해 `© Hayeon 2018-2026` 표시를 확인한다.
9. `/tokyo.html`, `/tokyo2.html`, `/tokyo3.html`에 접속해 번호 순서를 확인한다.
10. `/fukuoka.html`, `/fukuoka2.html`, `/fukuoka3.html`에 접속해 번호 순서를 확인한다.
11. document 계열 페이지에서 대표 이미지를 기본 배율로 확인한다.
12. 필요한 경우 pinch zoom으로 압축 노이즈, 흐림, 계조 손상을 확인한다.
13. 세로 방향을 우선 확인한다.
14. 가능하면 가로 방향으로 1회 회전해 overflow와 이미지 왜곡을 확인한다.
15. 각 페이지 결과표에 PASS/FAIL/HOLD/N/A를 기록한다.
16. FAIL 항목은 URL, 기기, iOS 버전, 재현 절차, 스크린샷 유무를 기록한다.

수동 검증에서 문제를 발견해도 바로 수정하지 않는다. 문제 내용과 재현 조건을 기록하고 후속 작업으로 분리한다.

| 판정 | 사용 기준 |
| --- | --- |
| PASS | 이미지 로딩, 품질, 레이아웃, overflow 기준에 문제가 없음 |
| FAIL | 로딩 실패, 과도한 품질 저하, 텍스트 겹침, 비율 왜곡, overflow 중 하나 이상 확인됨 |
| HOLD | 사용자 육안 판단이 필요하거나 기기별 차이가 있어 즉시 결론을 내리기 어려움 |
| N/A | 해당 페이지에 항목이 존재하지 않음 |

## 15. 미확인 항목 기록 방식

확인하지 않은 항목은 PASS로 기록하지 않는다. 다음 형식으로 기록한다.

| 항목 | 기록 방식 |
| --- | --- |
| 실제 기기 없음 | `HOLD - 기기 미보유` |
| 특정 viewport 미확인 | `HOLD - 해당 폭 미확인` |
| 이미지 품질 판단 보류 | `HOLD - 사용자 육안 판단 필요` |
| 페이지에 기능 없음 | `N/A` |
| 네트워크 문제로 확인 불가 | `HOLD - 네트워크 상태로 재확인 필요` |

## 16. 후속 작업 분리 기준

| 문제 유형 | 후속 작업 예시 |
| --- | --- |
| 특정 이미지 품질 저하 | 해당 이미지 최적화 기준 조정 |
| 다수 이미지 품질 저하 | JPEG 품질 또는 최대 변 기준 재검토 |
| overlay 겹침 | 모바일 CSS 레이아웃 수정 작업 |
| 번호 순서 오류 | Tokyo/Fukuoka 번호 렌더링 구조 수정 |
| footer 표시 오류 | footer HTML escape 처리 수정 |
| 가로 overflow | 모바일 CSS overflow 수정 |
| iPhone Safari 전용 문제 | Safari 호환성 수정 작업 |
| 원본 저장소 용량 문제 | 이미지 보관 정책 및 unused 정리 작업 |

## 18. ChatGPT 검토 요청 항목

- 체크리스트가 실제 수동 검증에 충분한지
- URL 목록이 대표성을 갖는지
- 이미지 품질 기준이 과도하거나 부족하지 않은지
- iPhone Safari와 Chrome viewport 검증의 역할이 명확히 분리되었는지
- 실패 항목 기록 양식이 후속 작업으로 연결되기에 충분한지
- 코드 변경 금지 조건이 지켜졌는지
